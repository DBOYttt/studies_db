# Studies DB — Plan 2: Discord Bot

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A discord.js bot that mirrors linked forum channels into the database (topics, tags, materials), downloads every attachment into content-addressed storage, catches up after downtime, and provides admin and student slash commands.

**Architecture:** Discord-free core modules (`sync.ts`, `ingest.ts`, `commands/*` handlers) take plain data objects and a `Db`, so they are tested against real MariaDB without Discord. A thin `discord/` layer maps discord.js objects to those plain types and wires events and commands.

**Tech Stack:** discord.js 14, `@studies/db`, Node 22 `fetch` + streams, Vitest 5, tsx.

**Spec:** `docs/superpowers/specs/2026-10-10-studies-db-design.md` (§5, §8)

**Depends on:** Plan 1 (`@studies/db`) complete.

## Global Constraints

- All Plan 1 global constraints apply.
- Only forum channels whose id is in `subjects.discord_channel_id` are processed; everything else is ignored silently.
- **No file-type or size limits.** Downloads are streamed to disk (never buffered whole in memory).
- Feedback reactions: ✅ new file stored, ♻️ file content already stored (same sha256), ❌ download/ingest failed.
- Admin commands require the member to have role `ADMIN_ROLE_ID`; others get an ephemeral `"Brak uprawnień."`.
- All slash-command replies are in Polish and **ephemeral**, except `/search`.
- `/link` reply: DM `"Twój link do Studies DB (ważny 15 minut, jednorazowy): <url>"`; ephemeral confirmation `"Wysłałem Ci link w wiadomości prywatnej."`; if DMs are closed, ephemeral `"Nie mogę wysłać DM — włącz wiadomości prywatne od członków serwera."`.
- Banned users running `/link` get `"Twój dostęp do strony jest zablokowany."`.
- Env: `DISCORD_TOKEN`, `DISCORD_CLIENT_ID`, `DISCORD_GUILD_ID`, `ADMIN_ROLE_ID`, `WEB_BASE_URL`, `DATABASE_URL`, `STORAGE_DIR`.
- Intents: `Guilds`, `GuildMessages`, `MessageContent` (privileged — without it Discord strips attachments from messages; enable it in the Developer Portal); partials `Message`, `Channel` for delete events.

## Review Focus

1. **Files posted in the forum post's starter message** — the starter message's `messageCreate` can arrive before `threadCreate` is handled. Expected: topic is created on demand and the file is stored. → Task 2 test `ingests when topic does not exist yet`.
2. **Bot restarted while students posted, then live events overlap with catch-up** — expected: each attachment stored exactly once. → Task 2 test (double ingest → `'exists'`), Task 4 catch-up test.
3. **Polish filenames / names with spaces, slashes or very long names** (`Sprawozdanie ćw. 3/4.docx`) — expected: stored by hash, original name kept in DB verbatim (truncated to 500 chars). → Task 2 test.
4. **Download fails mid-stream (network error / 404 from expired URL)** — expected: no DB row, no partial file left in `originals/`, temp file removed, result `'failed'`. → Task 2 test.
5. **Messages in non-linked forums, regular text channels or DMs** — expected: ignored. → Task 3 test.

### Task 2: Attachment ingest

**Files:**
- Create: `apps/bot/src/ingest.ts`
- Test: `apps/bot/test/ingest.test.ts`, `apps/bot/test/fixtures/sample.pdf`

**Interfaces:**

- Produces:
  - `AttachmentInput = { attachmentId: string; messageId: string; url: string; filename: string; contentType: string | null; size: number; postedAt: Date; uploader: DiscordUser; thread: ThreadInfo; threadOwner: DiscordUser | null }`
  - `IngestDeps = { db: Db; storageDir: string; fetchBody: (url: string) => Promise<ReadableStream<Uint8Array>> }`
  - `type IngestResult = 'created' | 'duplicate' | 'exists' | 'ignored' | 'failed'`
  - `ingestAttachment(deps: IngestDeps, a: AttachmentInput): Promise<IngestResult>` — `'ignored'` when forum not linked; `'exists'` when attachment id already in DB (checked **before** downloading); `'duplicate'` when created but sha256 file already on disk; errors logged, return `'failed'`.

- [ ] **Step 1: Write failing tests** (real test DB, temp `storageDir`, fake `fetchBody` returning a stream of the fixture):

  - `ingests when topic does not exist yet` — no prior `upsertTopic`; result `'created'`, topic row exists.
  - `second ingest of same attachment returns exists and does not download` — `fetchBody` spy called once.
  - `same content new attachment returns duplicate` — 2 material rows, 1 file on disk.
  - `keeps polish / slash filename verbatim` — `'Sprawozdanie ćw. 3/4.docx'`; stored path has no slash from filename; `convert` job.
  - `failed download leaves nothing behind` — `fetchBody` stream errors after first chunk → `'failed'`, no material row, `originals/` and temp dir empty.
  - `unlinked forum returns ignored without downloading`.
